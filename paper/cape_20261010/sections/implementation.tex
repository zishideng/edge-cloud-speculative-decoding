\section{Implementation}
\label{sec:impl}
\cape{} is implemented in the Python edge client of our testbed (Section~\ref{sec:testbed}). A lookahead client of 165 lines manages background draft calls to llama.cpp on a worker thread. It checks prefix compatibility and records every speculative token as reused, discarded or unused. \cape{} adds the 81-line pipeline model and the online estimators on top of it; the same code and settings run all four model pairs. Draft and target exchange token IDs, so no text is re-tokenized between rounds, and the draft server is not asked for token probabilities. The cloud verification service is a FastAPI front end to vLLM that returns the target's top-1 token at every draft position; it is identical for all methods. The baselines of Section~\ref{sec:eval} are implemented in the same client and share its transport, draft server and verification service. Every request logs per-round timings, all speculative events, every controller decision and the power trace, which allows each number in this paper to be recomputed from raw records.
